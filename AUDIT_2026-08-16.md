# my-vidwatch fresh audit — 2026-08-16

Scope: current 2.0.0 code after Phase 2 (`0900415`). This is a new audit; the old B-numbered report was never recovered, so none of those identifiers are reused.

Baseline: `python3 -m pytest tests -q` passes **109/109** on this machine. The findings below are therefore specifically cases where current tests permit silent degradation or contract violations.

## 1. High — ffmpeg detector failures are silently reported as “nothing detected”

**Locations:** `scripts/media.py:225-228`, `scripts/media.py:329-339`, `scripts/media.py:364-377`, `scripts/dedup.py:249-266`

`detect_cuts`, `keyframe_times`, `detect_silence`, and `content_changes` all run ffmpeg/ffprobe with `check=False`; several paths do not check `returncode` before parsing output. A filter/option/version failure therefore becomes an empty cut list, empty silence list, or empty content-change list. Downstream code can then classify a clip as static or “no silence” rather than reporting that measurement failed.

**Reproduce:** put a fake `ffmpeg` first on `PATH` that prints an error and exits 7, then call `media.detect_cuts(...)`, `media.detect_silence(...)`, and `dedup.content_changes(...)`. All three return `[]` with no exception. This was reproduced during this audit.

**Fix type:** contained. Distinguish a successful zero-result run from a non-zero process exit; surface the stderr tail as `VidwatchError`. The planned `defects` module should inherit the same rule for every ffmpeg detector.

## 2. High — custom `scan --grid` can exceed `--max-tokens`

**Location:** `scripts/vidwatch.py:291-349`

The scan budget solver prices a fixed `grid_for(25)` sheet before it knows whether the caller supplied `--grid`. Later, sheet construction uses the caller's actual grid. A grid larger than 5x5 can therefore create an image much larger than the one used for budget admission.

**Reproduce:** on an 8-second 640x360 fixture, run:

```bash
python3 scripts/vidwatch.py scan clip.mp4 --grid 10 10 --max-tokens 3000 --json
```

Observed during this audit: `est_image_tokens = 5076` for one `2618x1498` sheet, despite the 3,000-token limit.

**Fix type:** contained. Price the actual requested grid before admitting the scan, and verify final assembled-sheet cost does not exceed the limit. This matters before Phase 4 because its joint budget must not inherit an already-bypassable scan budget.

## 3. High — embedded subtitle cache ignores `--language`

**Locations:** `scripts/transcript.py:338-360`, `scripts/transcript.py:383-401`

`pick_subtitle_stream()` correctly uses `language`, but `_reusable()` treats cached `embedded` transcripts like URL captions and compares only `sub_langs`. For a local file, `sub_langs` is normally unchanged (`None`), so a transcript selected with `--language en` is reused when the next run asks for `--language zh`.

**Reproduce:** create an MKV with English and Chinese SRT tracks, then run two probes against the same cache:

```bash
probe dual.mkv --no-cuts --no-whisper --language en --json
probe dual.mkv --no-cuts --no-whisper --language zh --json
```

Observed during this audit: both runs returned `language=eng` and `english line`.

**Fix type:** contained. Cache identity for embedded subtitles must include the requested `language` (or the selected stream identity), while URL caption reuse should remain keyed by `sub_langs`.

## 4. Medium — local cache identity truncates mtime to whole seconds

**Location:** `scripts/cache.py:50-64`

Local cache keys use `path + size + int(st_mtime)`. Replacing a file with different bytes of the same size inside the same filesystem second produces the same key, so old metadata, transcript, cuts, and extracted frames can be reused for new content.

**Reproduce:** write 4096 bytes to one path, set mtime to `...000.1s`, compute `_key_for`, replace it with different 4096 bytes, set mtime to `...000.9s`, and compute again. Observed during this audit: both keys were `11e551c34ca89b59`.

**Fix type:** contained. Use `st_mtime_ns` (and preferably inode/device or a small fast fingerprint if cross-filesystem replacement semantics matter).

## 5. Medium — explicit `--timestamps` can be dropped by `--max-frames`

**Locations:** `scripts/vidwatch.py:409-440`, CLI contract at `scripts/vidwatch.py:885-889`

The CLI says timestamps are “always include these times (survive dedup)”. `cmd_read` protects them during dedup, but if the resulting list exceeds `cap`, the final `even_sample(kept, cap)` has no knowledge of protected timestamps and may remove them.

**Reproduce:** on a 6-second fixture:

```bash
read clip.mp4 --start 0 --end 6 --mode uniform \
  --max-frames 3 --timestamps 1 2 3 4 --no-dedup --json
```

Observed during this audit: returned timestamps were `0, 2, 4`; requested `1` and `3` were missing.

**Fix type:** contained. Treat explicit timestamps as outside the automatic frame ceiling, or reserve/merge them after automatic thinning. This also lines up with Phase 6 burst candidates, which must not be lost to a later baseline cap.

## 6. Medium — repeated `extract --out` runs leave stale deliverables in `frames/`

**Locations:** `scripts/vidwatch.py:678-684`, `scripts/vidwatch.py:698-730`

`extract` creates/reuses the output directory but does not clear or manifest-prune old frame files. Re-running into the same `--out` with a different frame count/layout leaves old images beside the new output. The skill tells hosts to surface files from that folder, so stale evidence can be handed to the next reviewer.

**Reproduce:** run `extract --layout frames --frames 6 --out OUT`, then rerun the same clip with `--frames 3 --out OUT`. Observed during this audit: the folder grew from 6 JPEGs to **8**, rather than containing the 3 current deliverables.

**Fix type:** contained, but cleanup must be scoped only to my-vidwatch-owned generated files in the selected output directory. A safer alternative is a unique run subdirectory plus an explicit manifest.

## 7. Low — millisecond timestamp formatting can emit `.1000`

**Location:** `scripts/util.py:86-96`

`fmt_ts(..., ms=True)` rounds the fractional milliseconds after the whole-second component has already been fixed. Values at or above a 999.5ms fraction can therefore print a four-digit millisecond field without carrying into the next second.

**Reproduce:** `fmt_ts(1.9995, ms=True)` returns `00:01.1000`; `fmt_ts(59.9996, ms=True)` returns `00:59.1000`.

**Fix type:** contained. Round total milliseconds first, then split into hours/minutes/seconds/milliseconds.

## Design-decision items skipped

No newly found blocker requires a product/design decision before Phases 4-7. The findings above are contract/correctness fixes. One broader policy remains intentionally unscoped: URL cache freshness. URL cache identity is the URL string and downloaded media is reused indefinitely; changing that requires a TTL/revalidation policy and is not needed for the planned phases.

## Planned-phase conflicts

- **Phase 4 (joint frame × resolution budget):** Finding 2 must be accounted for so a custom scan grid cannot bypass the new visual budget. The new budget must never reduce frame count.
- **Phase 5 (`defects`):** Finding 1 is directly relevant. A detector process failure must never be encoded as “no defect”. Existing `detect_silence`, `content_changes`, and transition confirmation should expose measurement failure distinctly.
- **Phase 6 (burst sampling):** Finding 5 is directly relevant. Candidate/burst timestamps need stronger protection than the current explicit timestamp path.
- **Phase 7 (docs):** no conflict beyond the already logged documentation issues in the audit brief.
